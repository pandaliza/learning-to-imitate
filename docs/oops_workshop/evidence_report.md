# Evidence report: future-intent conditioning under spatial shifts

Status 2026-10-05 ~19:00 EDT: **READY_WITH_EXPLICIT_LIMITATIONS** for a re-scoped paper.

- Part A (rollout evidence): a matched, validity-checked spatial-shift study of a flow-matching policy **with vs
  without conditioning on a predicted future end-effector pose** (robomimic square-mh-state), run locally.
- Part B (evaluation pitfall): an audit showing the project's earlier pi0.5 / LIBERO-Goal perturbation results are
  invalid, with the mechanism verified in the simulator.

The pi0.5 comparison in the original spec (`oops_workshop_robustness_spec.md`) was **not run**: its checkpoints
exist only on the cluster, which was unavailable. Nothing in Part A may be described as a pi0.5 or LIBERO result.

## A. Matched spatial-shift study (robomimic square-mh-state)

Facts and protocol: `docs/oops_workshop/square/methods_facts.md`. All numbers below are regenerated by
`analyze_robustness.py` / `square_breakdowns.py` from `oops_runs/square_manifest_pv1` (frozen before any rollout)
and `oops_runs/square_episodes_pv1` (one JSONL record per episode, checkpoint sha256 + evaluator hash
`736bb5a805a08fd6`). Outputs: `docs/oops_workshop/square/results/`.

**Coverage.** 1,550 physical cases (50 native resets x [delta=0 + 3 deltas x 10 directions]); 1,550/1,550 valid by
the pre-policy probe; 1,550 matched pairs completed per arm; 0 infrastructure errors, 0 policy failures,
0 missing pairs.

Change from delta=0: baseline -0.21 / -0.41 at 0.05 / 0.10 m; flow-intent -0.10 / -0.32. The difference in

cohort's delta=0 estimate with 3 seeds is 0.43, against a deterministic baseline at 0.46.

**Supported wording:** "Across 1,550 matched initial configurations, conditioning on a predicted future
end-effector pose did not produce a consistent robustness improvement. The success-rate differences were
-0.08 to +0.03, with every 95% interval including zero, and both policies fell to about 5-6% success at 10 cm shifts."
**Not supported:** equivalence, "intent hurts", or "intent helps".

**A2. Pre-registered breakdowns (descriptive, raw counts).**
- Distance of the nut's start outside the demonstrated start range: SR inside 0.46 / 0.38; 0-2 cm 0.40 / 0.42;
  2-5 cm 0.19 / 0.22; 5-8 cm 0.05 / 0.04; >8 cm 0.01 / 0.01 (baseline / intent). Both policies fail once the
  nut starts a few centimetres outside the demonstrated range. Bins mix deltas and directions, so this is descriptive.
- Direction: shifts along y (the axis the demonstrations vary 11 cm in) degrade less than shifts along x (5 mm
  demonstrated range): at delta=0.05, y-dominant 0.33 / 0.33 vs x-dominant 0.20 / 0.24.

**A3. Paired outcomes are only weakly coupled.** At delta=0.02, 238 of 500 pairs are discordant (116 baseline-only,
122 intent-only successes). Consistent with A5: a 1-ulp change in the physics re-evaluation changes trajectories,
so per-case pairing mostly controls for initial configuration, not for rollout noise.

**A4. Checkpoint labels overstate clean performance.** The file names' 0.62 / 0.64 are each run's final (and best)
50-episode training-time evaluation. Earlier evaluations: baseline 0.16-0.32, intent 0.36-0.58 (19-eval mean 0.47).
The untouched native pipeline reproduces 0.56 / 0.42 on 150 episodes.

**A5. Parity with the native evaluator.** First observation and first action chunk are bit-identical. Divergence
starts after one step and comes from the single extra `mj_forward` inside `reset_to`; adding one redundant forward pass to
the native path alone produces divergences of the same size (up to 4e-2 in actions). Outcome-level agreement:
baseline 0.46 vs 0.56 (deterministic policy; 2 vs 7 discordant resets, sign test p ~ 0.18), intent 0.43 vs 0.42.

**A6. Native tool defects found (not fixed in place).** `examples/eval/eval_success_rate.py` crashes (unpacks 4
of `collect_rollouts`' 5 return values; ROOT path stale since the move to `examples/eval/`). It also defaults to
NFE 1, where the documented baseline SR is 0.18 vs 0.44 for the intent model; NFE 9 (the checkpoints'
documented metric) is used here.

## B. Evaluation pitfall: the earlier pi0.5 / LIBERO-Goal perturbation results are invalid

**B1.** Before commit `5f06c5d` (2026-08-03), `eval_libero_perturbed.py` used qpos addresses as indices into
robosuite's flattened `[time, qpos, qvel]` state. Verified on the libero_goal MJCF for all 8 eligible tasks:

- `dx` was added to a gripper-finger joint or a neighbouring object's quaternion;
- `dy` was added to the target's world x, so the target moved only by delta·sin(theta) along x, and not at all for theta in {0, pi};
- validity, "fell" and "no_reach" labels were computed on `[junk, x, y]`.

Every M0 / M1 / M3 / DINOv2 / DynaFLIP / co-train XY-perturbation table and failure cascade in the project notes
came from this code. **B2.** The notes' claim that object x positions have zero training variance is false: in
the 500 LIBERO-Goal demos each object's start x and y have std ~0.9 cm. **B3.** Physics-only validity on the
corrected LIBERO perturbation, local provisional manifest (`docs/oops_workshop/manifest_local_provisional/`):

| delta | invalid | unknown |
|---|---|---|
| 0.05 m | 19% | 5% |
| 0.10 m | 41% | 9% |

Invalid placements are mostly overlaps with neighbouring objects. By contrast, the square scene has 0% invalid,
so whether validity filtering matters depends on the scene.

## Limitations (state in the paper)

- One task; one training run (seed 0) per arm: no training-seed variance.
- Training budgets differ: 50k vs 190k gradient steps, so this is not a controlled ablation of the intent pathway.
- Weak base policies (clean SR about 0.4-0.5).
- delta=0 reference from 50 episodes.
- One policy seed in the primary analysis (3 seeds as a secondary analysis; the baseline is deterministic).
- Validity probe and thresholds are engineering choices (inactive in this scene).
- Initial-position shifts of one object only. This study does not test recovery, imperfect demonstrations or learning from failure.
- The intervals are conditional on these checkpoints and this task.
